_General hardening settings are available for all Patchstack paid plan users._  
**_Protection is available for WordPress sites only._**


General hardening settings include WordPress behavior changes and server-file rules. They can be enabled independently of the PHP firewall. See [how hardening and security headers work](/patchstack-app/site-dashboard/hardening/hardening-and-security-headers-explained/).

To manage your site's hardening settings, navigate to **Sites** > **yourdomain.com** > **Hardening** in Patchstack App.

![](@images/patchstack-hardening-general.png)

On this page you can manage the following hardening settings:

<Steps>
1. **Disable the theme editor** - disables both the plugin and theme file editors in WordPress
2. **Remove readme.html from the WordPress root folder** - this will attempt to stop basic readme.html scans by bots or visitors
3. **Block readme.txt access**
4. **Disable user enumeration** - restricts anonymous author-ID requests, the REST users routes and the users sitemap; authenticated requests still follow WordPress permissions
5. **Hide WordPress version** - this feature removes the WordPress version in the &lt;meta> tag in the HTML output
6. **Block WordPress application password feature** - this feature disables the application passwords feature introduced in WordPress 5.6
7. **Restrict XML-RPC Access** - disables WordPress XML-RPC methods, including password-authenticated methods and anonymous pingbacks. Methods registered by another plugin may remain available
8. **Restrict WP REST API Access** - restricts anonymous REST requests, with an exception for Contact Form 7 routes. It does not grant additional permissions to authenticated users
</Steps>
