_Additional protection settings are available for all Patchstack paid plan users._  
**_Protection settings and modules are available for WordPress sites only._**

The **Additional settings** subpage is found at **Sites** > **yoursite.com** > **Protection** > **Additional settings** in Patchstack App.

![](@images/patchstack-protection-additional-settings.png)



## Additional settings features

### Protection settings

**Enable firewall** - this toggle enables or disables Patchstack's firewall. When turned off, your site won't be protected by virtual patches or firewall rules. However, other security measures (such as IP bans and .htaccess rules) will remain active. We recommend disabling the firewall only for testing purposes.

**Enable auto-prepend firewall** - this beta feature configures PHP's <a href="https://www.php.net/manual/en/ini.core.php#ini.auto-prepend-file" target="_blank">auto_prepend_file</a> to inspect supported PHP requests before WordPress loads, including scripts outside WordPress core. Automatic installation supports compatible Apache 2.4 and LiteSpeed environments; its reach depends on the PHP and directory configuration. On multisite, the primary site of the primary network controls installation and removal of the shared server configuration. Subsites can refresh their own rules in an existing installation.

**Redact firewall logs** - when turned on, blocked requests are still logged, but without the submitted form data (POST and raw request body) and without the URL query string. A blocked login attempt to `/wp-login.php?log=admin&pwd=secret`, for example, is logged as `/wp-login.php` with the payload shown as redacted. This keeps usernames and passwords out of your site's database and out of the logs sent to Patchstack, even when the firewall blocks a legitimate request by mistake. Entries that were logged before you turned this on are redacted too before they are sent to Patchstack. The trade-off is that redacted entries no longer show which payload triggered the block, and alert rules that match on the payload will not fire for them. This setting is off by default and is available on sites running Patchstack plugin version 2.3.8 or newer.



### User role whitelist

The user role whitelist exempts selected roles from firewall rules that respect that whitelist. Some rules can still apply to whitelisted roles, and checks that run before WordPress identifies the current user cannot use its role. To configure the whitelist:
<Steps>
1. Navigate to your sites' **Protection** > **Additional settings** page in Patchstack App
2. Look for the **User role whitelist** section
3. Toggle the roles, that you wish to whitelist
4. Click **Save settings** once the changes have been done.
</Steps>

### General whitelist settings

Under the **General whitelist settings** section, you can manage whitelist settings and add IP address header override rule.

> #### 📘 Whitelist
> 
> Each rule must be on a new line.
> 
> The following keywords are accepted  
> IP:IPADDRESS  
> PAYLOAD:someval  
> URL:/someurl
> 
> Definitions  
> IP = firewall will not run against the IP  
> PAYLOAD = if the entire payload contains the keyword, the firewall will not proceed  
> URL = if the URL contains given URL, firewall will not proceed
> 
> Example  
> IP:192.168.1.1  
> PAYLOAD:contact_form  
> URL:water  
> URL:/some-form
> 
> In this scenario, the firewall will not run if the IP address is 192.168.1.1 or if the payload contains contact_form or if the URL contains water or if the URL contains /some-form.

> #### 📘 IP Address Header Override
> 
> If you would like to override the IP address header that we use to grab the IP address of the visitor, enter the value to IP Address Header Override input.
> 
> This must be a valid value in the $\_SERVER array, for example HTTP_X_FORWARDED_FOR. If the $\_SERVER value you enter does not exist, it will fallback to the Patchstack IP grab function so ask your hosting company if you are unsure.
> 
> Leave this empty to use the Patchstack IP address grabbing function.

### Block IP settings

In this section, you can Block IPs that are a potential threat to your sites.

![](@images/1f3457c-patchstack_block_ips.png)

> #### 🚧 Example case:
> 
> Patchstack has blocked 5 attacks on your site from one specific IP address in a period of 60 minutes.  
> You would now want this IP to be blocked.
> 
> Type in the following data:
> 
> Block IP for **4320** Minutes  
> After **5** Blocked Attacks  
> Over A Period of **60** Minutes
> 
> Click **Save Settings**
> 
> Now - any IP address which meets all those conditions will be blocked for three days.
>
> Genuine WordPress cron execution is exempt from automatic firewall IP bans so scheduled jobs can still run. Its request is still inspected against firewall rules; a request parameter named `doing_wp_cron` does not grant this exemption. The manual IP block list is separate.

> #### 📘 IP Block List
> 
> Lets you completely block IP addresses by entering each IP address to a new line.
> 
> Following formats are accepted:  
> 127.0.0.1  
> 127.0.0.\*  
> 127.0.0.0/24  
> 127.0.0.0-127.0.0.255
